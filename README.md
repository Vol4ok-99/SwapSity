# SwipeCity для GitHub Pages

Положите содержимое архива в корень репозитория. На GitHub откройте **Settings → Pages**, выберите **Deploy from a branch**, вашу основную ветку и папку **/ (root)**. После сборки GitHub покажет URL в разделе Pages.

Для локальной проверки запустите в папке сборки `python -m http.server 8001` и откройте http://localhost:8001.

Каталог, фильтры, карта, свайпы, сохранённые места, посещения и отзывы работают в браузере. История хранится только на текущем устройстве и в текущем браузере. Аккаунты, друзья и групповые комнаты требуют серверной версии. Карте и внешним фото нужен интернет.


## Карта и проверка мест

Карта использует браузерный движок SwipeCity и растровую подложку OpenStreetMap. Светлая и тёмная темы используют один источник. Действуют [правила использования тайлов OSM Foundation](https://operations.osmfoundation.org/policies/tiles/). Запрашиваются только видимые тайлы, кеширование выполняет браузер по HTTP-заголовкам, атрибуция остаётся на карте. Публичный сервис работает без гарантированного уровня доступности.

Для проверки опубликованных карточек запустите `python verify_catalog.py`. Команда `python verify_catalog.py --online` дополнительно проверяет URL источников, ссылки на изображения и лицензии Wikimedia Commons. `python verify_catalog.py --discover candidates.json` получает кандидатов из Overpass и записывает их отдельно с `verified: false`.

Перед публикацией карточки вручную сверяйте адрес по официальному источнику, координаты по OSM или Wikidata, а фото по странице объекта на Wikimedia Commons. Сохраните `source`, `coordinate_source`, `verified_on`, 1–3 лицензированных фото с авторами и только после этого выставляйте `verified: true`. Новый импорт не публикует карточки автоматически.

## Локальный конвейер каталога

Требуется Python 3.10+. Скачайте или склонируйте эту версию и откройте PowerShell в папке проекта. Первый запуск создаёт `catalog-work.sqlite3`; опубликованный JSON используется как исходная версия.

    python catalog_pipeline.py import
    python catalog_pipeline.py import --file candidates.json
    python catalog_pipeline.py process --limit 20
    python catalog_pipeline.py stats
    python catalog_pipeline.py review

Для импорта достаточно одной из первых двух команд. Откройте напечатанный адрес `http://127.0.0.1:8031/`. Редактор доступен только на loopback. В карточке есть сравнение исходных, новых и опубликованных полей, источники и журнал. Для подтверждения укажите независимый источник идентичности, который подтверждает конкретный адрес или объект. Подходящие фото можно отметить отдельно. Для разрешённого стороннего фото добавьте в JSON `permission_photos` с `author`, `attribution`, `source`, `url` и `permission_url`. Последняя ссылка должна указывать на документированное разрешение; его содержание сверяет редактор.

Для пошагового запуска используйте `process --stage normalize`, `duplicates`, `enrich`, `facts`, `photos`, `queue` в этом порядке. `--id` можно повторить для выбранных записей. `--offline` использует кеш. Записи с временной ошибкой ждут `retry_at`. Клиент ограничивает частоту запросов, кеширует успешные ответы на сутки и повторяет запросы с паузой, учитывая `Retry-After`. HTTP-доступность страницы не считается подтверждением места.

    python catalog_pipeline.py stale --days 90
    python catalog_pipeline.py process --limit 20
    python catalog_pipeline.py export
    python catalog_pipeline.py export --apply

`stale` ставит устаревшие записи на перепроверку. Для свежего снимка геометрии перед этим выполните `import`. `export` формирует `catalog.staging.json` и `catalog.report.json`. После просмотра команда с `--apply` резервирует `catalog.previous.json` и атомарно заменяет локальный `catalog.json`. Веб-публикация остаётся отдельным действием. При явном отклонении опубликованной записи её ID сохраняется для истории, а флаг выдачи выключается. При объединении старый ID связывается с основным через `canonical_id`; адресная близость сама по себе приводит только к подсказке редактору.

Для планировщика Windows или n8n задайте рабочую папку проекта и последовательно запускайте `import`, `process --limit 20` и `export`. Для параллельной ручной проверки можно держать открытым редактор. Пользовательские решения применяются к локальному каталогу отдельно. Не добавляйте `--apply` в автоматическую цепочку, если нужен предварительный просмотр.

### Расширенный сбор мест и фотографий

`import` собирает именованные места в границах города, в том числе памятники, библиотеки, спортивные объекты, пекарни и площадки для досуга. Повторный импорт сопоставляет записи по ID OSM. Парки и открытые памятники можно подтвердить по координатам и независимому источнику. Для заведений нужен адрес. Если адреса нет в OSM, конвейер может взять его со связанного сайта, когда точное название и близкие координаты подтверждают конкретное место.

`process` начинает с кандидатов, у которых есть ссылки на источники и фотографии. `photos` отдельно ищет снимки для уже обработанных карточек, включая подтверждённые карточки без фото. Поиск использует ссылку OSM, Wikidata, статью Википедии и Wikimedia Commons. В редактор попадают предложения с автором, источником и подходящей лицензией. Совпадение по названию требует сверки изображения. В подтверждённой карточке кнопка **Подтвердить только фото** сохраняет остальные поля, в том числе адрес и дату проверки. Временный сбой поиска изображений не задерживает решение по фактам.

    python catalog_pipeline.py photos --limit 50
    python catalog_pipeline.py review
    python catalog_pipeline.py export

`process` и `photos` можно запускать порциями или с `--all` для всей доступной очереди. Прогресс сохраняется после каждой записи. `stats` показывает состояние очереди. `export` сохраняет только одобренные записи и до трёх одобренных фото на карточку. Для заведений, которых нет в Wikimedia Commons, можно использовать редактор и поле `permission_photos` для собственного фото или снимка с документированным разрешением.

### Автоматическая публикация

```powershell
python catalog_pipeline.py auto-publish
```

Команда получает свежий список OpenStreetMap, пропускает закрытые места, дубли и записи с известными конфликтами, затем записывает каталог сайта. Подтверждённые редактором карточки сохраняются. Адрес, режим работы, телефон, описание и сайт берутся из заполненных полей источника. Карточка без адреса ведёт к точке на карте. В интерфейсе у импортированных записей указаны источник и дата выгрузки.

Программа сама прикрепляет до трёх фотографий с подходящей лицензией по прямой ссылке на файл или точной привязке к объекту в Wikidata и Wikimedia Commons. Фото из поиска по похожему названию остаются вне автоматической выгрузки. Места, для которых подходящий снимок не найден, доступны на карте и в ленте.

`auto-publish --file candidates.json` использует сохранённый снимок OSM и ищет фото в сети. Для запуска без сети добавьте `--offline`. Отчёт `catalog.auto-report.json` содержит причины пропуска, а `catalog.previous.json` хранит предыдущую версию каталога. Для другого города используются те же параметры `--city-config`, `--db` и `--catalog`.

### Импорт другого города

Сохраните конфигурацию в `city.json`. Пример формата с границами Рязани, порядок координат `[юг, запад, север, восток]`.

```json
{"name":"Рязань","bounds":[54.54,39.55,54.75,39.92],"language":"ru"}
```

Замените название и границы. Для каждого города укажите отдельную базу и отдельный JSON каталога. Они могут ещё не существовать. Укажите область самого города, поскольку сбор по прямоугольнику может включать соседние населённые пункты.

```powershell
$cityArgs = @('--city-config', 'city.json', '--db', 'city.sqlite3', '--catalog', 'city-catalog.json')
python catalog_pipeline.py @cityArgs import
python catalog_pipeline.py @cityArgs process --limit 50
python catalog_pipeline.py @cityArgs photos --limit 50
python catalog_pipeline.py @cityArgs review
python catalog_pipeline.py @cityArgs export
```

Проверка выгрузки с карточками: `python verify_catalog.py --city-config city.json --catalog city-catalog.staging.json`. Выгрузка самостоятельна. Для показа нескольких городов потребуется поддержка выбора города в браузере.

### Необязательный адаптер ИИ

Команда `suggest` отдельно запускает указанный вами Python-адаптер только для записи со статусом `needs_review`. Она принимает выбранный редактором фрагмент до 1800 символов, кеширует результат по содержимому и резервирует лимит перед запуском. Следующий пример задаёт микроденежные единицы в одной валюте для всего рабочего файла SQLite.

    python catalog_pipeline.py suggest --id osm:node:123 --fragment excerpt.txt --adapter adapter.py --max-records 10 --budget-micros 100000 --reserve-micros 10000

Адаптер получает JSON через stdin с полями `fragment`, `task`, `budget_micros` и возвращает `{"suggestion":"..."}`. Вызываемый адаптер должен самостоятельно обеспечивать верхнюю границу стоимости у своего провайдера. Локальный лимит учитывает резерв, а не фактический счёт провайдера. Ключи, если они нужны выбранному адаптеру, остаются в его окружении. Предложения хранятся отдельно и не меняют факты, публикацию или очередь.

Проверки: `python -B -m unittest -v test_catalog_pipeline`. Для пилотной базы в комплекте можно открыть очередь сразу: `python catalog_pipeline.py --db pilot.sqlite3 review`.
